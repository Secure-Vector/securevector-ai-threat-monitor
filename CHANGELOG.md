## [5.2.0] - 2026-08-19

### Added
- **Cost / Token Optimizer** *(Cost & Tokens → Optimizer)* — Cost Tracking answers *how much*; the Optimizer answers *why*, and *what to change*. An opt-in local scan of the session transcripts already on this device (same consent contract as Instant Audit: read locally once, keep aggregate numbers and content hashes only, delete any time, nothing uploaded) rebuilds each session's generation sequence and partitions its waste into two non-overlapping buckets: **cache waste** (carried context billed at the full input rate that an achievable caching policy — provider minimum prefix, TTL, amortized write premium all honored — would have served at the cache-read rate) and **compaction waste** (context beyond a "keep the last 10 turns + a summary" counterfactual, valued at the cache-read rate so the two buckets sum instead of stacking). Eight detectors emit ranked findings: repeated context with the breakeven turn where compaction would have paid for itself, tool-result carry (the turn-12 file read you re-bought on turns 13 through 60), low cache utilisation with the hit rate against a published threshold, retry loops (identical arguments with an error between repeats; known-idempotent read tools excluded), duplicate LLM requests (transport retries deduped by request id first), excessive output against the call-shape median (abstains below n=20), abnormal loop shape scored against the agent's own baseline, and model right-sizing — which ships as a raw observation plus "run an evaluation", never a verdict, because a model swap trades quality for cost. **Findings are attributable or absent**: every one names its session and turns, deep-links to the exact generation in Traces, and the trace waterfall annotates those turns in place — the ranked list is discovery, the annotation is proof.
- **The with/without comparison strip** — observed spend/tokens for the window next to the modeled figure under the achievable counterfactuals, which is exactly the sum of the lower-bound buckets, so the strip and the findings list cannot disagree by construction. Always labelled a modeled estimate. Every estimator is a lower bound, nothing extrapolates beyond the observed window, token counts are exact and dollar figures are list-price estimates — the product never claims an invoice will move.
- **Billing-mode aware units** — one shared analysis, two leading units. Metered API billing leads with dollars ("an estimated $X of avoidable spend"); subscription mode leads with tokens and frames value as usage headroom, because on a subscription the invoice will not move and claiming otherwise costs trust. Auto-derived where possible (proxy-metered means API-metered), asked once otherwise, reversible under Cost Settings. Never a tier or paywall split.
- **Recommendations, offered not imposed** — the first time findings exist the Optimizer asks; accepting turns on per-finding recommendations that lead with their benefit in your billing mode's unit, then the change and its evidence. Declining leaves Detect and the comparison fully functional. Reversible under Cost Settings.
- **Impact receipts** — findings have a lifecycle. When the metric behind a recommendation moves in its direction across like-for-like windows (7 days or 10 sessions of after-evidence, whichever is later), the finding resolves with a **measured** before/after from real sessions — no longer a claim. Below the minimum window it says "not enough sessions yet" rather than showing a delta; a resolved finding that backslides reopens with its history intact.
- **Shareable savings card** — one-click export of the comparison strip (or a measured receipt) as a PNG: observed → modeled figures, bucket percentages, window length, app version. Zero session content — no prompt text, session names, paths, or hostnames — and the estimate/measured label is baked into the pixels so the honesty caveat travels with the screenshot. Clipboard or file, no social integrations, no cloud round-trip.
- **Per-run limits** *(Cost Settings)* — enforcement, riding the deny rails the product already has. Everything ships **off**. A **max tool-calls-per-run cap** and a **loop breaker** (published thresholds: 10 identical calls or a sustained 30/min rate inside a 3-minute window) deny further tool calls in Claude Code, Codex, Copilot CLI and Cursor via the existing synced-overrides decision path, now carrying the session identity. **Per-run cost and token ceilings** extend the daily budget's warn/block model to the run, enforced at the proxy — the token ceiling is the subscription-mode counterpart and needs no pricing table. Every stop writes an audit row naming the control, the observed value and the threshold (it lands in the Blocked Actions ledger, grouped by that reason), and every stop is promotable in one click: "allow this run to continue" mints a session-scoped, time-boxed, revocable exemption on the JIT-grant contract, itself audited. A stop reports as "stopped before exceeding the limit", not as a bill after the fact.
- **First-open discovery** — a one-time spotlight for upgraders whose body is a native render of the Optimizer panel (clearly-labelled synthetic data until a real scan has findings, then your own top finding and total), the what's-new banner, an Optimizer tour step for fresh installs, and unseen markers on the tab. One appearance each, ever.
- **SecureVector Guard plugin for OpenCode** *(Integrations → OpenCode)* — the Guard family's sixth harness. OpenCode (1.18+) loads plugins as in-process ES modules, so this one needs no subprocess hooks: `tool.execute.before` carries the decision, and a deny raises before the tool runs. One-click install from the Integrations page (or `securevector-app --install-plugin opencode`) stages the plugin and registers it in `~/.config/opencode/opencode.json`; uninstall reverses both. Decisions ride the same synced-overrides policy path as Claude Code, Codex, Copilot CLI and Cursor — same audit rows, same Blocked Actions ledger, same JIT exemptions. OpenCode session tokens (read from the `session` table of OpenCode's local database, cumulative per-session counters) join the Session Tokens by Runtime card on Cost & Tokens, and the Connect Agents detection rail reports OpenCode coverage like every other harness.
- **The Guardian reacts to what actually happened** *(Guardian assistant)* — the character had two states and one gesture, and its idle motion ran on infinite tweens: it moved identically whether the machine was quiet or an agent had just been blocked, which is what makes perpetual motion read as a screensaver rather than as attention. Idle is now **procedural and settles** — after a quiet spell the bob, sway and shadow decay toward a floor, so any movement at all becomes a signal. On a real finding the Guardian **looks at the surface that finding belongs to** (the nav entry, falling back to the section header when the sub-item is collapsed, and doing nothing when the target is off-screen), then reacts in a register that matches the event: a sharp refusal and a held beat of stillness for a threat, a secret catch or a blocked call; a lean-in with narrowed eyes for a context or budget warning. `wave()` goes back to being only a greeting, since a denied tool call did not deserve a friendly nod. The state vocabulary grows from three to five (`idle`, `scan`, `listening`, `concerned`, `ok`) and the SVG fallback carries the same five, each legible from static shape alone. **No state is expressed in colour** — posture, eye shape and luminance only, because colour in this product means security state and nothing else — and every new behaviour stays behind `prefers-reduced-motion`. Reactions ride the sentinel's existing per-category cooldown rather than a new timer, so a busy agent fleet cannot strobe the character.
- **Live advice names the agent it is about, and prints its own disclaimer** *(Guardian panel)* — every live card and every spoken line said "a live session", which is unusable when four agents are running and the user has to know which window to act in. Cards and bubbles now read **Agent #N · <id>**, numbered from the same activity list the Optimizer's session list numbers from so one session cannot carry two names across the app, with a second line giving the handle a human can actually match to a terminal: the runtime, the model, and how long ago it last moved. A session missing from that list stays unnumbered rather than taking a number that would disagree. The copy button confirms its destination ("Copied, paste into Agent #2") instead of "paste it into your session". And the Live section now prints the promise that previously lived only in a source comment: **advisory only, SecureVector never types into a session and never edits your files, you copy the fix and paste it yourself**, with context figures marked as measured from the local transcript and everything else as a modeled estimate.
- **The Guardian docks instead of wandering** *(Guardian assistant)* — the bot relocated itself to a random ink-free point every 26 seconds, and after eight failed attempts it moved to the ninth candidate **without checking it**. On a real dashboard that meant parking on the banner copy, where it faded to a grey shape that reads as a rendering fault rather than a character, and standing mid-column on the Optimizer, where it read as an asset dropped in the wrong place. Chasing empty space with a smarter picker does not work on a dense page, because every candidate covers something. It now **docks** in the corner the layout already reserves for it, drag-to-pin still puts it wherever the user prefers, and the only automatic movement left is stepping a **user-pinned** bot off text it is sitting on, ranked by least ink and nearest, keeping the pin at the corrected spot. The fade over text drops from 0.32 to 0.14 (a legible grey shape reads as a smudge; this reads as out of the way) and now runs on first paint instead of waiting for a scroll, so the bot no longer sits opaque on top of a button until you touch the page. `_coversInk` also counts controls that hold no text: the app's toggles are `label > span` with a zero-size input, so a switch previously registered as empty space.
- **The Guardian panel moves too** *(Guardian assistant)* — the panel drags by its header, the way the bot drags by itself, and reopens where it was left. Header only, deliberately: the body scrolls and is full of click targets, and the close control stays a click rather than the start of a drag. Movement past a 6px threshold counts as a drag, so an ordinary click on the header still does nothing. Default behaviour is unchanged, the panel follows the bot; once it has been moved, the moved position wins on every open. Positions are re-clamped into the current viewport on open and on resize, so a spot saved in a wider window cannot leave the panel, or its close button, out of reach.
- **The Optimizer closes its own loop: copied, pasted, worked** *(Cost / Token Optimizer, Guardian)* — every copy button on the page put a fix on the clipboard and then stopped caring, so a fix that was never pasted looked exactly like one that fixed the problem. A copy now starts a follow-through clock. The service watches the transcripts already on this machine for the copied text turning up as a user turn, and once it does, re-measures the condition the advice was about. Three states, and the gap between them is the point: **copied** is certain (we filled the clipboard ourselves), **pasted** is read from the local transcript, and **worked** is measured — context actually shrank, or the flag that caused the advice stopped coming back. Only the third is ever celebrated; congratulating someone for pasting would be the same modelled-as-measured overclaim the rest of this page refuses to make. Fixes that are never pasted expire silently, because an unused suggestion is the user's call and not something to nag about. A **Fixes you copied** band on the page carries the same three states with the before and after numbers, and the panel now discloses the watching up front. Detection reads transcripts only: no clipboard reads, no keystroke watching, nothing written into a session.
- **The Guardian has a personality, and a thought cloud to put it in** *(Guardian assistant)* — the bot watched in total silence between alerts, which made an ambient character feel like an idle graphic. It now has five documented traits — calm, precise, modest, kind, dry — written into the source as the thing new copy gets checked against, and a thought cloud above its head: three dots while work is genuinely in flight (they go up before a request and down after it, so the cloud cannot fake being busy) and a short thought when nothing needs doing. The cloud cannot be clicked, so it is barred from making any claim about the user's data: an unlinked "a tool result is misbehaving somewhere" is a finding with no evidence attached, and findings go through the speech bubble, which carries the number and a button to the page that owns it. What is left is the bot talking about itself, the time of day, how long the human has been at it, and how long nothing has happened. Humour never appears in an advisory, a finding or an alert. Every colour is a theme token, so the cloud follows light / black / azure / ember / slate without a per-theme rule, and it fades and moves with the bot rather than floating over an almost-invisible one.
- **A verified fix gets a lap** *(Guardian 3D and flat renderers)* — the one showy moment in the product: 270 degrees on the vertical axis, a short unwind back to front, and a ring of drifting colour around the button. It fires on a measured win and on nothing else. The Guardian's own materials are never touched, because hue on this bot means security state; the colour lives entirely in a transient ring that means nothing and is gone in under two seconds. The ring is drawn in the DOM rather than the scene: inside a 94px canvas it sat on the silhouette edge and clipped away to nothing. This also fixed a latent bug in every one-shot move — the idle drive **assigns** body height and body yaw every frame, so any tween writing those same properties was wiped before it could be seen; one-shot moves now drive an offset the drive adds in.
- **The fill gauge stopped guessing, and autocompact stopped stealing wins** *(Cost/Token Optimizer, live advisor)* — the context-fill percentage divided by a model-name lookup (200K, or 1M for a `[1m]` suffix), which is a guess, and it showed: a session once read "118% full". The denominator now comes from evidence in the transcript itself. Claude Code writes a `compact_boundary` record with the trigger and the exact context size at which compaction fired; an auto-triggered boundary's `preTokens` IS the effective ceiling, because autocompact is user-configurable per session (600K on a 1M window makes the model max the wrong number), and with no such boundary the lookup is raised to the observed context peak whenever the peak disproves it, so fill can never exceed 100 again. The same records fixed a false-win path in fix follow-through: with autocompact on, context can drop with no help from the pasted fix, and the Guardian would have celebrated the harness's work as the user's. A compact-type fix whose after-window contains an auto-triggered boundary now resolves to a new honest state, shown on the receipt as "context came down, but auto-compact did it. Not counting that one as yours." A manual compact after the paste still counts, because running the compact is what the pasted fix asks for.
- **The Guardian learned restraint** *(Guardian assistant)* — an ambient character lives or dies on how rarely it speaks, and the first cut of the thought cloud mused roughly once a minute, which is a colleague who never stops talking. Everything the bot says now shares one clock: a bubble, an orientation or a thought each push the next thought back, thoughts start no sooner than five minutes after the last word and each one pushes the next further out (capped at twenty minutes), the first musing waits until two minutes into the session, and an orientation never lands within half a minute of something just said. The thinking dots also stopped flashing on every routine 45-second poll: work has to actually take a moment before the indicator appears, so dots once again mean “this is taking a moment” instead of ticking like a metronome. The cloud itself got a softer entrance and a slow resting drift, both switched off under reduced motion.
- **The Guardian offers the short version of whatever you just opened** *(Guardian assistant)* — expanding a trace, a threat, or a policy is the moment someone wants orientation, and it is the moment no product ever offers it. Expanding anything on a known page now brings a two-sentence brief: what the view is, and the one thing worth looking at first, with a button to the page that follows on. Detection is generic (`aria-expanded`, `<details open>`, `.expanded`, `.open`), so no page needs to know the Guardian exists. Discipline, because this is the easiest feature in the app to make annoying: once per page per session, three times in total, never over an alert or an open panel, and every line ends by handing control back. The briefs explain the product and never describe the user's data, so nothing in them can be wrong about what is on screen.
### Notes
- The Optimizer analyzes; the per-run limits enforce; nothing in this release modifies a request body, rewrites a prompt, or changes which model answers. Automatic model routing and prompt rewriting were considered and rejected — silently restructuring a request makes every downstream behaviour change unattributable, and attribution is this product's entire claim.
- Codex transcripts carry no correlated tool calls, request ids or stop reasons, so the retry, duplicate and loop detectors **abstain with a stated reason** there rather than reporting "no waste found".
- OpenClaw's plugin cannot deny at the plugin layer, so tool-boundary stops are proxy-only for that runtime; the ceilings require the proxy to be running and say so in the UI.
- Schema v45: `session_id` on `llm_cost_records` (the proxy already derived a stable per-conversation id; now it is stored), run-limit settings on `app_settings`, and a `trace_id` index on `tool_call_audit` for the per-run counter.

## [5.1.0] - 2026-08-06

### Added
- **Agent Egress Governance** — a destination policy enforced at the Guard-plugin tool boundary. Network destinations are extracted from `WebFetch`, remote MCP calls, and best-effort `Bash` argv analysis, then evaluated against a policy that lives outside the agent context and outside the harness config, so the agent cannot read it, argue with it, or be told it does not exist. The model turns on a read/write asymmetry: reads (`pip install`, `git clone`, docs fetches) are recorded and allowed, while the narrow unambiguous write classes are denied by default. Three presets — **Baseline** (on by default, needs no tuning by construction), **Hardened** (allowlist-only writes), and **Contained** (full allowlist, intended as a per-run mode rather than a global setting). Every deny is promotable in one click, and the promotion rate is surfaced as a policy-health signal: a policy whose denials are all promoted is reported as mis-set rather than left to be disabled. Schema v44 adds `egress_policies`, `egress_audit` (one row per destination reached, not per tool call), and `containment_proofs`.
- **Baseline egress rule pack** — package/registry publish (pypi, npm, cargo, docker, gem), the cloud instance-metadata endpoint `169.254.169.254` (waivable on CI runner profiles that legitimately read instance credentials), known anonymous drop sites, pushes to a git remote given as a literal URL, and reaches into RFC1918 private space. Every rule is rare in normal work and unambiguous when it fires, which is what lets Baseline ship on by default without ever needing maintenance.
- **Egress enforcement across all five Guard runtimes** — Claude Code, Codex, Copilot CLI, Cursor, and OpenClaw. Tool-permission rules govern *whether* a tool may run; egress governs *where* it may reach, so a tool allowed by name can still be denied for its destination. Cursor is wired at `beforeShellExecution` and `beforeMCPExecution`, which are its natural egress points; OpenClaw consults egress in its existing post-hoc tool-audit loop. Runtimes name their shell tool differently (`Bash`, `shell`, `exec`, `run_terminal_cmd`), and a name missing from a runtime's capability set would silently disable enforcement for it, so a test asserts the per-plugin sets stay a superset of the server's.
- **Blast-radius inventory** — the distinct external hosts this device's agents actually reached, with call counts, write counts, and first/last seen. The headline counter reports the destination count rather than a blocked-events count, because the destination count stays meaningful when the policy is working and nothing is being blocked at all, and it tracks how many of those hosts were seen for the first time this week.
- **Counterfactual policy replay** — re-decides destinations this machine already recorded under a candidate policy and reports exactly what would have changed: which calls flip to blocked, which hosts are responsible, and how many would clear with one promotion each. This is what makes Hardened and Contained enableable; switching presets blind is an unbounded bet on tomorrow's workflow, and replay converts it into a number the operator can read first. It states its own limits: it bounds known breakage, not all breakage, and Baseline verdicts are carried over from the recorded row rather than re-derived, because the flags they match on come from the original command, which is deliberately not stored.

- **Scope-expansion alerting** — measures the *shape* of a session's egress rather than each destination in isolation: how many distinct hosts it reached, how many this device had never contacted before, and how fast. The 2026-08 eval-containment incident scanned roughly nine thousand hosts, and not one of those requests would have tripped a destination rule, because scanning nine thousand hosts is nine thousand ordinary-looking reads. The signal was only ever in the count. Alert-only by design: a rate threshold is a heuristic, and a heuristic that halts a test suite legitimately fetching two hundred fixtures is a heuristic that gets switched off within a week. It also refuses to fire before the device has a baseline, since on a fresh install every host is novel and a detector that cries wolf on day one is muted before it ever sees a real event. Thresholds are published rather than hidden in a score, so an operator who disagrees can disagree with a number.
- **Local detections light up the cloud console** *(story #197 Phase 2)* — enrolled + consented devices now forward local rule-detection verdicts (BLOCK / DETECTED scans) over the existing fleet uplink as metadata-only scan-verdict rows: verdict, severity, threat-type labels, scan id, timestamps — never prompt text, model output, or the text a rule matched. The rows ride the same outbox (queue, backfill, circuit breaker) and the same enrollment consent as tool-activity forwarding; ALLOW scans stay on-device, and declined devices forward nothing. This is the local half of the sync that stops the cloud Overview reading zero for machines whose protection runs entirely locally — the cloud aggregates them into per-org detection counts, clearly labelled as local-rule verdicts, never summed with cloud ML analyses. The enrollment disclosure now states detection forwarding explicitly.
- **Agent Egress page** *(Govern → Policies & Controls)* — two tabs. **Destinations** is the blast radius, with one-click promotion; hosts blocked by a rule a promotion cannot clear show "policy edit" instead of an Allow button that would silently do nothing. **Policy** carries the preset selector with the counterfactual preview inline, plus the promotion-rate health signal.

### Security
- Credential shapes (bearer tokens, `-u user:pass`, API keys, JWTs, PATs, private keys) are redacted from stored egress evidence at extraction time, before any caller can persist them. SecureVector never takes custody of a secret.
- **Forwarded detections now report enforcement, not opinion.** The scan-verdict rows sent to the cloud console derived "blocked" from the *verdict* — what the rules judged the event deserved. On a device running in monitor-only mode (`block_threats` off) every BLOCK verdict is recorded as `logged` and the prompt goes through, so the cloud console was reporting those threats as stopped while the device's own dashboard said "threats allowed through — review now". Two consoles contradicting each other about the same events, with the cloud one overstating protection. The enforcement outcome (`action_taken`) is now carried on the forwarded row at every redaction tier and is what decides `blocked`, matching the local dashboard's own test exactly. Rows queued before this change carry no enforcement field and degrade to "detected" — they are still counted as detections, but never claim an unearned block.

### Notes
- Egress enforcement is defense-in-depth at the agent tool boundary, **not** network isolation. A process reaching the network by a path the hooks do not cover (an inline interpreter, a compiled binary) is out of view, and a remote MCP server is an egress proxy whose downstream destinations are not observable.
- **Containment Proof is withheld from this release.** The feature was built and then cut before shipping, so nothing is being removed from anyone. Two reasons. It did not establish its own claim: the probes evaluate the policy in-process, never crossing the installed hook, this app's API, or the harness, so a machine where the plugin was never installed still returned `contained`. And it sent live requests from the user's machine to third parties (an anonymous drop site, the cloud instance-metadata address, npm, PyPI) to establish, in a healthy deployment where every dangerous path is blocked before execution, only that the machine has internet access. The `/api/egress/proof*` routes, the service, and the `containment_proofs` table remain in place and unreferenced by the UI. The replacement being considered is a zero-egress enforcement self-test that drives a synthetic event through the installed hook and contacts nobody.

## [5.0.0] - 2026-07-31

### Added
- **Traces** (formerly Agent Runs) — full-page agent list drilling into a stepped waterfall per run: tool calls with allow/block verdicts, per-step cost, triage chips, a verdict minimap, and in-trace search. **Live follow** streams a running session (pausable without the page moving), **session replay** steps chronologically through the redacted event stream, and a one-click **audit PDF export** produces a session/time-range compliance report. A "while you were away" digest strip summarizes what happened since the last visit.
- **Instant Agent Audit** — a local, opt-in retroactive scan of past Claude Code / Codex session history already on this device: risky calls, secrets touched, and spend from before any hook was installed. Sortable columns, CSV export, deterministic audit checklist. Nothing leaves the machine.
- **Six selectable themes** — a hover theme menu on the rail (dark, light, and four accent variants); choice persists per device.
- **Preliminary Posture Score on first ingest** — the protection posture is scored as soon as the first data lands rather than after a warm-up window.
- **Runtime Connect Wizard** — guided detect → protect → verify flow: scans this device for agent runtimes (Claude Code, Codex, Copilot CLI, Cursor, OpenClaw, frameworks), installs Guard with one click per runtime, and verifies the first protected call live. New left-nav Connect entry; the manual per-agent command sets remain under Connect Agents / Integrations.
- **One-click cloud trial from the local app** *(Settings → Cloud)* — a "Start a free 30-day cloud trial" CTA that runs an OAuth-style device flow: the app requests a device code, opens the browser to the signup page, polls for completion, and stores the returned `svpk_` key itself — no key to copy. Falls back gracefully to the manual paste path when the cloud endpoint isn't available (`trial_unavailable`). Metadata-only; same consent gates as a manual connect.
- **JIT (just-in-time) tool access requests** — an agent that hits a *requestable* deny can file a time-boxed access request; a human approves or denies it on the Tool Permissions page. Org hard denies never queue (requests against them are rejected at creation and cannot be overridden locally). Approval mints a grant of 15 minutes, 1 hour, or the requesting session only — there is deliberately no "until I revoke". Grants surface to the Guard hooks as high-priority allows scoped per runtime (and per session for session grants); revoke-now is one click; request/grant lifecycle rows are their own audit trail. Schema v43: `jit_access_requests` + `jit_access_grants` + a `requestable` flag on synced rules (cloud policies mark which denies may be requested; local Blocks are implicitly requestable). All four Guard plugins (Claude Code, Codex, Copilot CLI, Cursor) file requests on requestable denies and honor session-scoped grants.
- **LLM I/O visibility in Agent Runs** — expanding a scanned step now lazy-loads the exact content excerpt SecureVector inspected for that call (from the correlated threat-intel record), with action / threat-type / risk context. Privacy posture unchanged: the app never records full prompt/response bodies — only what was scanned, and only while "Store text content" is on.

### Changed
- **v5 experience revamp** — the release's headline. Navigation regrouped into **Observe / Govern / Connect** (all page ids and deep links unchanged); **Cmd+K command palette** for keyboard navigation with recents; dashboard recomposed into a three-tier protection hero; threat details now lead with **one plain-language sentence** ("Blocked: this traffic contained an attempt to modify a protected system file.") with the technical breakdown below; a quiet motion layer (page-entrance transition, card hover lift, Agent Map flow animation) that fully disables under `prefers-reduced-motion`.
- **Triage consolidated into Threat Monitor** — Blocked Actions and Secret Detections are no longer separate left-nav destinations; they are facets of Threat Monitor, which is now the single answer to "what did SecureVector catch or stop?". Each facet keeps its own renderer rather than being flattened into a shared table: Blocked stays an aggregate grouped by the policy that fired, with hit counts, and Secrets keeps its own shape. Both page ids remain routable and open the matching facet, so deep links and bookmarks are unaffected. Top-level nav rows now honour `aliases` (previously only sub-items did), so the Threat Monitor row stays lit on those routes.
- **Observability simplified to three tabs** — Map / Runs / **Sessions** (renamed from Storylines; the industry-standard term). The old Timeline page is now the "Live feed" view toggle inside Runs. Sessions' "Open this run in Agent Runs" deep-links to that exact run's waterfall.
- **Cost Tracking, Tool Activity & Tool Inventory restyled** — runtime-colored identity dots replace the alert-looking panel borders (colors now match the observability pages), compact stat chips replace oversized stat cards, friendly empty states for the token trend chart and proxy cost summary, audit-chain re-verify joins the toolbar, and the Inventory column glossary collapses behind a toggle.

## [4.8.0] - 2026-06-21

### Added
- **Framework SDKs for LangChain, LangGraph, and CrewAI** — three pip-installable adapters (`securevector-sdk-langchain`, `securevector-sdk-langgraph`, `securevector-sdk-crewai`, all Apache 2.0 on PyPI) that secure agent **tool calls** — tool-call permissions, secret / data-leak detection, and threat detection — with a two-line wrapper and no proxy or base-URL change. LangChain/LangGraph attach `secure_middleware()` via `create_agent` (a denied tool is short-circuited with a `ToolMessage`); legacy chains can use the observe-only callback handler. CrewAI wraps tools with `secure_tools()` or patches globally via `install()`. Every decision is written to the same tamper-evident audit chain with `runtime_kind` attribution (`langchain` / `langgraph` / `crewai`), so SDK tool calls appear in the **Agent Map** and **Agent Runs** alongside the native plugins. `observe` mode (default) logs an advisory verdict and always runs the tool; `enforce` mode blocks. Each SDK package also installs this local app.

## [4.1.1] - 2026-04-27

### Fixed
- **Desktop app hang on Cmd+Q / window close (macOS)** — `run_desktop()` launched uvicorn as a daemon thread with no shutdown handshake. pywebview's Cocoa run loop waits for the daemon thread to drain on shutdown; uvicorn's event loop holds long-lived connections (SSE / keepalive) that never return, so the process hung and only force-quit recovered. Fix: register a `window.events.closing` handler that calls `os._exit(0)` immediately on user-triggered close, plus a backstop `os._exit(0)` after `webview.start()` returns. There is no per-process state to flush — DB writes are committed inline; logs are best-effort.
- **`--web` mode SIGINT shutdown latency** (`run_web()` and `start_server()`) — passed `timeout_graceful_shutdown=1` to `uvicorn.run()` so in-flight request drain caps at 1 second instead of waiting indefinitely. Halves Ctrl+C exit time (10.8s → 5.4s in measurement). Safe for SecureVector's request profile: scans complete in ms, SIEM forwarders run on background workers, SQLite WAL is atomic per-statement.
